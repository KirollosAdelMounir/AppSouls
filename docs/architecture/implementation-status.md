## Implemented

The five-project solution has Domain definitions, Core capabilities, DataConnection repositories/contexts/migrations, Infrastructure business services and the Blazor Application. `AGENTS.md` mandates shared controls, animations, focus behavior, theme persistence and reduced motion.

Identity sign-in uses cookies, confirmed-email identities, password lockout, rate limits and explicit tenant membership selection. Authenticated operations recheck membership and user security stamps. Static account pages handle cookie changes. TOTP enrollment and one-time recovery codes are implemented, with MFA optional for all roles as approved on 3 November. The privileged-MFA gate is removed. The primary login contains email/password only; protected continuation handles named workspace selection and verification only for explicitly enrolled accounts. Identity token values and the persisted authentication key ring are encrypted. Initial setup creates the first platform administrator and vendor-owner membership through token-free first-time setup, with database locking against concurrent claims and permanent closure after an identity exists. Owners/admins can create staff and customer accounts and enable/disable workspace access through `/users`. Local CLI provisioning also remains available; global platform administration is a separate database flag.

Server settings are backed by a versioned AES-GCM vault, with a separate protected unlock key and explicit recovery commands. appsettings JSON files are removed. Platform administrators can configure PostgreSQL/SQL Server connections, SMTP and named future-integration credentials. Stored secrets are never returned to the page. Blank values preserve secrets. Database changes are staged for restart; SMTP settings update the running sender. Vault and data-protection files live outside the repository/webroot.

PostgreSQL and SQL Server have separate EF migrations. Tenant filters, immutable tenant ownership, composite tenant foreign keys and optimistic concurrency protect persistence. Migrations run only through an explicit administrator command. PostgreSQL is exercised locally with an isolated password-protected development database.

Working CRM screens/API support customers, software catalog, contracts, contract activation and purchased entitlements. The `/sales` pipeline adds paginated leads and opportunities, owners, expected values/currencies, UTC follow-ups, validated stages, application-immutable history and atomic, retry-safe conversion of qualified leads into a new customer and opportunity. Customer reads are restricted to their own company and purchased software. Database-backed counts replace invented metrics; queries are bounded to 100 records.

Support reports submit under authenticated customer entitlement, atomically persisting ticket, initial history and acknowledgement outbox. Staff view their vendor inbox and progress reports through Submitted, Received by a technical member, Solution in progress, Completed and Closed. Receipt requires assignment; completion and closure require resolution/reason. Customer history excludes internal notes. Repeated submissions are operation-bound; stage transitions store request digests and operation IDs for safe retries. The SMTP worker resolves the verified reporter, claims jobs with leases, retries with bounds and never equates queued with delivered. SMTP is initially disabled pending operator configuration.

Licensing provides immutable primitive model publication, extension validation, C#/JavaScript/Java/Python exports, purchased-installation enrollment, installation capacity concurrency checks, signed/encrypted issuance, manual downloads and a machine-credential renewal endpoint. Artifacts use AES-256-GCM, RSA-OAEP key wrapping and separate RSA-PSS issuer signatures. The server never receives the installation private key. Renewal retrieval remains available after a usage term expires, subject to revocation and authentication. Only implemented profiles are advertised.

All HTTP business and account handlers use attribute-routed controllers in `TicketingCRM/Controllers`. The former `Endpoints` folder is removed. Scalar at `/scalar` renders the generated OpenAPI document at `/openapi/v1.json`; outside development both require platform-administrator authorization. Cookie/antiforgery and installation bearer authentication are documented without exposing secrets.

The light blue/dark Blazor UI includes the shared selector, calendar/time picker, persistent appearance preference, keyboard focus, navigation/page motion and reduced-motion overrides. Authenticated screens now invoke business services rather than exposing fake submission controls.

### Provider execution-strategy error fix

Reproduced a SQL Server connection failure wrapped by `SqlServerExecutionStrategy` in `InvalidOperationException`. Setup error classification previously handled only top-level provider errors, causing both testing and activation to return a generic activation failure. The classifier now inspects bounded inner exceptions for known database, TLS, socket and timeout failures and returns fixed, nonsecret messages. Connection checks now log failure type, safe category and code locations, without raw exception messages or credentials. Unexpected database/email checks no longer claim that an activation was attempted.

`ExecutionStrategyWrapperPreservesProviderFailureCategoryWithoutExposingMessages` verifies wrapped provider failures and nested timeouts. Focused setup/failure run: Passed: 12, Failed: 0, Skipped: 0; solution build passed without warnings/errors. Read-only live checks against the operator-specified local SQL Server (1433) and PostgreSQL (5432) confirmed both credentials connect when TLS is disabled. Required TLS failed certificate validation on SQL Server and failed PostgreSQL's TLS connection; these are server TLS configuration constraints, not password-policy failures. Live setup endpoint checks verified successful connections and explicit missing-catalog classifications for both providers. No accounts, databases, schemas or saved configuration were changed by these checks.
