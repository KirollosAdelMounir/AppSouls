# Workspace expansion security requirements — v1

7 November 2026. Applies to forms/Excel, commercial records/PDF, support conversations and private attachments, release distribution and native database row policies. This is implementation evidence, not an ASVS certification. The target remains OWASP ASVS 5.0.0 Level 2 with selected Level 3 privileged/cryptographic requirements.

## Boundaries and controls

- Authenticated membership, current security stamp and an active tenant authorize every service operation. Customer IDs submitted in a request do not establish ownership. New staff roles are checked by service capability, not merely by navigation visibility.
- Commercial documents resolve their customer and order/contract relationships before insertion. Recorded orders and issued invoice snapshots cannot be edited or deleted through persistence. Stable operation IDs reject changed retries. PDF prices use bounded decimal inputs and per-line rounding; supplier/buyer tax references are descriptive fields, not tax-authority validation. Issuance is limited to Owner/Admin/Sales Manager; pricing approval is Owner/Admin.
- Public form capabilities resolve only a published form in an active tenant. Draft edits use optimistic versions; published question sets and received answers are immutable. Extra answer keys and invalid typed values are rejected. XLSX exports encode user strings as inline text, never formulas; only validated number/rating columns use numeric cells. Exports are private, capped at 10,000 responses, streamed into a temporary file and deleted on disposal.
- Customer chat creation checks purchased software for Technical inquiries and active catalog software for Sales inquiries. Staff can read/reply only to their inquiry team (Owner/Admin can supervise both). Persistent messages have stable retry identifiers, bounded length, rate/quota checks and immutable author/time metadata. Customer rendering replaces private employee names with team labels. Two-second polling rechecks authorization even when the conversation version is unchanged; it does not claim an agent is online.
- Ticket replies use tenant/customer ownership and preserve the five-stage workflow. Attachments authorize ticket/reply ownership before reading the stream, enforce safe filenames/extensions, 20 MiB/file, 50 files/200 MiB per ticket and 5 GiB per customer. Quota allocation serializes through tenant/ticket versions. A clean scanner verdict is required before metadata becomes downloadable; failures delete temporary artifacts. Replays compare parent, actor, filename and content digest. Downloads reauthorize and verify the digest. Raw HTML and active links/images/styles are excluded from rendered Markdown.
- Installers stream up to 8 GiB (8,589,934,592 bytes) in the Blazor browser flow; a clean scan and signed immutable manifest are required before binary publication. ClamAV cannot inspect files at or above 2 GiB. Such packages remain quarantined. Configured scan/stream/archive limits can impose lower limits. The multipart HTTP endpoint retains its approximately 514 MiB request limit: native IIS filtering cannot represent an 8 GiB single request. No 8 GiB native/proxy transfer qualification is claimed.

## Native database row policies

`NativeRowSecurity` migrations contain frozen V1 SQL for 27 tenant tables in PostgreSQL and SQL Server. Business connections enter `appsouls_runtime` and receive parameterized tenant/customer/public-form session scope; scope is reset before returning connections to the pool, and reset failures clear the pool. Missing tenant scope sees no tenant rows. Runtime has table DML permissions and no migration-history permissions. PostgreSQL uses NOLOGIN/NOSUPERUSER/NOBYPASSRLS and FORCE ROW LEVEL SECURITY; SQL Server uses a user WITHOUT LOGIN and filter plus insert/update block predicates.

All 27 tables enforce tenant scope. Direct customer-owned records (customers, contracts, entitlements, installations/licenses, orders/invoices, customer activities, support tickets/chats/messages/replies/attachments and memberships) additionally enforce the selected customer. Internal sales/pricing/invitation/form-management rows are unavailable to customer scopes. Public form scope accesses only its form/submissions and its tenant quota row. Shared product/schema/release rows remain tenant scoped; application services enforce entitlement and publication rules. Outbox and ticket history have native tenant scope, with parent ownership and customer-visible history enforced by their services. Global Identity tables retain their existing identity-store and specialized-directory authorization; they are not tenant tables and do not receive native tenant policies. This is not database column-level redaction of identity data, staff names or internal history.

Migration/activation, password-verified identity-directory discovery, credential-verified machine licensing, public capability location and installation/background repositories use explicit narrow administrative persistence. Generic missing scope does not opt into that privilege. Initial activation remains explicit; later migrations run before HTTP/outbox services start and must fail startup on upgrade failure. The upgrade identity needs PostgreSQL role-creation/grant authority or SQL Server database-owner/equivalent authority to create policies and the restricted principal. An unrelated principal with the reserved name is rejected.

These policies defend against omitted application filters and wrong row writes. They do not protect against stolen administrative credentials, arbitrary SQL execution that changes session scope/role, a compromised server process, or a privileged database operator. Administrative credentials remain protected by the vault. Applications must continue to use parameterized queries, revalidate membership and perform resource authorization. SQL Server policy scripts are generated, but native SQL Server execution and pooled impersonation qualification remain release requirements.

## Protected DLL distribution

DLL encryption is **not implemented in this phase**. A usable runtime eventually exposes executable code in memory; encryption/obfuscation cannot guarantee prevention of reverse engineering. A loader with a universal embedded private key would create a misleading control and is prohibited.

A separate distribution phase must evaluate commercial obfuscation/loader compatibility and licensing, signed manifests, per-installation key provisioning, authenticated encryption, offline startup, key rotation/recovery, expiry-safe renewal access and native Windows/Linux/FreeBSD behavior. No private issuer keys may be included in client artifacts. Until this is implemented and qualified, do not advertise encrypted DLL delivery or reverse-engineering immunity.

## Chat follow-up controls — 2026-11-07

Chat files require a currently active authenticated membership, authorized conversation and an existing message authored by the uploader. Composite database keys bind tenant, customer, conversation and message. Metadata is immutable; private files are bounded, scanned before metadata publication, integrity-checked on download, and removed on failed publication. Native row policies cover the new table in each provider migration. Ticket/chat storage share the customer quota. Invalid retries cannot replace an accepted artifact. Malware-scanner unavailable/rejected verdicts and unsafe filename extensions fail closed. Browser receipt is distinct from scan/persistence success; download handoff does not certify a disk save.

Typing can change only the authenticated customer's/staff's side of an authorized conversation. Throttled heartbeats expire after eight seconds; no private participant names are returned. Customer/staff alert queries revalidate membership and conversation/team access and exclude the viewer's own messages. Read receipts derive their user from authentication, validate the referenced message/parent and only advance the read watermark. Per-user unread counts persist in tenant/customer-scoped rows with native provider policies. On-screen alerts contain a generic message and authenticated conversation link; the sound is a public static asset and contains no credentials. Browser session state stores only bounded message identifiers, partitioned by user/tenant. Read receipts are durable; polling/session sound state does not provide offline push delivery.

Customers cannot use lifecycle, commercial-document services or their downloads to bypass the restricted workspace. Disabled membership is rejected before message/file consumption. Sign-in reveals the contact-company state only after password verification; invalid credentials retain a generic response. Native SQL Server and multi-instance workload qualification remain outstanding.

Clipboard uploads are untrusted browser files and use the same shared upload stream, size/filename limits, author/parent authorization, malware scanning and private storage as chosen files. Clipboard text/URLs are not fetched as remote artifacts. A failed upload retains its existing saved-message association for retry; neither success text nor an attachment record is published before scanning/persistence completes.
