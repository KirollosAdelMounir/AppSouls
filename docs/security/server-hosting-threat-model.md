# Server hosting security requirements v1

Scope: privileged deployment helpers, runtime downloads, Linux/nginx/systemd and Windows/IIS/ANCM hosting. The administrator running the installer and the complete published package are trusted. This is an implementation threat model, not an independent security certification. Baseline remains the proposed OWASP ASVS 5.0.0 L2 with selected privileged L3 requirements.

| ID | Requirement | Evidence and limits |
| --- | --- | --- |
| HOST-DOWNLOAD-1 | Select the app's stable channel; validate vendor download origin and SHA-512 before using runtime code. Windows also checks Microsoft's Authenticode signer. | `test_selects_supported_matching_latest_patch_and_rejects_untrusted_urls_or_old_channel`, `test_runtime_download_verifies_digest_before_code_is_used`; Windows helper tests reject spoofed/plaintext vendor URLs. Native Authenticode execution still needs Windows qualification. |
| HOST-PACKAGE-1 | Reject incompatible runtime identifiers, unsupported/pinned frameworks, traversal/link/device runtime archive entries and unbounded extraction. | Runtime/package and archive cases in `test-server-setup.py`; actual Microsoft runtime extraction/list-runtimes verification. Full App Souls package signing is not implemented by these helpers. |
| HOST-PRIVATE-1 | Code remains read-only to the application; vault/key/artifact paths stay outside public content. Do not adopt unrelated state, sites, accounts or configuration. | `test_proxy_and_service_preserve_https_websockets_streaming_and_privilege_boundaries`, `test_owned_configuration_is_atomic_and_unmanaged_or_linked_paths_are_preserved`, `test_deployment_refuses_unmanaged_destination_and_upgrade_without_explicit_switch`; Windows ACL and virtual account setup implemented, native validation pending. |
| HOST-PROXY-1 | Accept one symmetric forwarded client/scheme hop only from the explicit nginx loopback peers. nginx replaces incoming forwarded headers. Do not trust forwarded host headers. | `HostingProxyTests.test_only_explicitly_enabled_exact_loopback_proxy_can_supply_symmetric_forwarded_headers` checks disabled, trusted, asymmetric and untrusted 127.0.0.2 cases against the built production host. |
| HOST-IIS-1 | Preserve ANCM's allocated port and pairing-token validation rather than expose a standalone application listener. | `HostingProxyTests.test_iis_allocated_port_and_pairing_token_take_precedence_over_standalone_listener` simulates ANCM variables and rejects missing/wrong pairing tokens. This does not qualify actual IIS/Windows. |
| HOST-TLS-1 | Default to local-only HTTPS; generate no publicly trusted certificate claim. Protect TLS keys; reject mismatched replacement keys/certificates before overwriting valid files. | `test_tls_is_private_and_mismatched_replacement_preserves_existing_certificate_and_key`; self-signed certificates are explicitly labeled. Native Windows certificate/ACL handling and operator CA renewal remain qualification work. |
| HOST-UPGRADE-1 | Require an explicit upgrade switch, preserve state/key material, retain previous release directories and fail readiness without silently rolling binaries back across database migrations. | `test_full_mocked_install_and_failed_upgrade_preserve_state_and_stop_new_service` exercises staged files, retained identity material and stop-on-failure. Crash/power-loss recovery and native reboot readiness are not yet qualified. |
| HOST-SCAN-1 | Configure a local scanner/updater; do not equate PING with a clean package or fresh signatures. | Scanner helper tests, real local clean/EICAR checks and per-package quarantine gate. Scanner engine/archive/limit/freshness qualification remains required. |

Existing root/administrator compromise is outside the filesystem boundary. Runtime/scanner sources depend on trusted vendor HTTPS, release metadata and the OS trust store. Online scanner fallback without WinGet accepts a stable official MSI only after its GitHub release SHA-256 digest check and rejects invalid signatures; offline MSIs require a valid signature as well. Host packages, TLS certificates, private runtimes and scanner definitions need ongoing operator patching/renewal. SELinux network-connect permission is broader than a single destination and is documented in deployment instructions.

Before production: exercise clean privileged installation, native Windows IIS and Linux nginx, reboot/service initialization, browser Blazor reconnect/upload limits, trusted TLS renewal, update failure, migration failure, backup/key recovery and interrupted deployment under a versioned deployment matrix. Native FreeBSD application hosting is outside this installer. No high/critical risk acceptance is granted by these tests or documents.
